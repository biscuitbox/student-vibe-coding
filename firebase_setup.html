파이어베이스 설정 절차서

강사 전용 · 수업 전 한 번만 · 소요 20~30분

학생은 이 페이지를 볼 일이 없습니다. 파이어베이스 프로젝트는 선생님이 하나만 만들고, 학생에게는 설정값 한 덩어리만 복사하게 합니다. 학생 20명이 각자 콘솔을 만지면 한 차시가 통째로 날아가고, 만 14세 미만은 프로젝트 생성 자체가 막힙니다.

5차시까지 준비해야 할 것

준비물어디에 쓰나
파이어베이스 프로젝트 1개반 전체가 공유
구글 로그인 켜기5차시 로그인
Firestore 데이터베이스할 일·점수 저장
보안 규칙남의 데이터 보호 — 가장 중요
firebaseConfig 값학생이 복사해 붙여넣음

절차

1 프로젝트 만들기

console.firebase.google.com 접속 → 프로젝트 추가 → 이름은 학교·학년이 드러나지 않게 짓습니다(예: web-class-2026).

Google 애널리틱스는 끄세요. 수업에 필요 없고 설정만 길어집니다.

2 웹 앱 등록하고 설정값 받기

프로젝트 개요 화면에서 </> 모양 웹 아이콘을 누릅니다. 앱 닉네임은 아무거나. 호스팅 설정은 체크하지 마세요(배포는 깃허브 페이지로 합니다).

등록이 끝나면 const firebaseConfig = { ... } 코드 덩어리가 나옵니다. 이걸 통째로 복사해 두세요. 아래 6단계에서 씁니다.

3 구글 로그인 켜기

왼쪽 메뉴 빌드 → Authentication → 시작하기 → Google 선택 → 사용 설정 → 지원 이메일을 고르고 저장.

다른 로그인 방법은 켜지 마세요. 특히 전화번호 인증은 유료입니다.

4 승인된 도메인에 배포 주소 넣기

Authentication → 설정 → 승인된 도메인. 여기 없는 주소에서는 로그인 창이 열리지 않습니다.

  • localhost — 보통 이미 들어 있음
  • 깃허브 페이지 주소 — 배포한 뒤 반드시 추가

여기에는 도메인만 넣습니다. 배포 주소가 https://내아이디.github.io/web-class/라면 등록할 값은 내아이디.github.io입니다. https://와 뒤쪽 저장소 경로는 빼세요. 경로까지 넣으면 등록이 되지 않습니다.

계정 하나에 저장소를 여러 개 만들어도 도메인은 내아이디.github.io 하나뿐이라, 이 값은 한 번만 등록하면 됩니다.

6차시에 갑자기 로그인이 안 되는 사고는 대부분 이 단계를 빠뜨려서 생깁니다.

5 Firestore 만들기

빌드 → Firestore Database → 데이터베이스 만들기.

  • 위치: asia-northeast3 (서울)
  • 모드: 프로덕션 모드로 시작 — 다음 단계에서 규칙을 직접 넣습니다

테스트 모드는 30일 뒤 전부 막히는데, 하필 수업 도중에 막히면 복구할 방법이 없습니다.

6 보안 규칙 붙여넣기 — 가장 중요

Firestore Database → 규칙 탭. 기존 내용을 전부 지우고 아래를 붙여넣은 뒤 게시를 누릅니다.

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // 내 데이터 — 본인만 읽고 쓸 수 있음
    match /users/{uid}/{document=**} {
      allow read, write: if request.auth != null
                         && request.auth.uid == uid;
    }

    // 게임 점수 — 누구나 읽기, 자기 기록만 쓰기
    match /ranking/{docId} {
      allow read: if true;
      allow create, update: if request.auth != null
        && request.auth.uid == request.resource.data.uid
        && request.resource.data.score is number
        && request.resource.data.score >= 0
        && request.resource.data.score <= 1000000
        && request.resource.data.nickname is string
        && request.resource.data.nickname.size() <= 12
        && request.resource.data.game is string
        && request.resource.data.game.size() <= 30;
      allow delete: if false;
    }

    // 전시관 작품 목록 — 누구나 읽기, 자기 작품만 쓰기
    match /gallery/{docId} {
      allow read: if true;
      allow create, update: if request.auth != null
        && request.auth.uid == request.resource.data.uid
        && request.resource.data.title is string
        && request.resource.data.title.size() <= 40;
      allow delete: if false;
    }

    // 그 외 모든 경로는 차단
    match /{document=**} {
      allow read, write: if false;
    }
  }
}

이 규칙이 하는 일은 딱 세 가지입니다. 내 할 일은 나만 본다, 점수는 모두가 보되 내 기록만 내가 고친다, 지우기는 아무도 못 한다.

5차시에 학생에게 이 규칙을 직접 읽히세요. 한 줄씩 짚으면서 "이 줄이 없으면 어떻게 되는가"를 물으면 개인정보 보호가 추상적인 구호가 아니라 코드가 됩니다. 이 수업에서 가장 값진 10분입니다.

7 학생 배포용 설정값 만들기

2단계에서 복사한 firebaseConfig를 아래에 붙여넣으면, 학생에게 그대로 줄 코드 블록이 만들어집니다. 워크벤치의 복사 버튼에 넣으세요.

이 값은 공개되어도 되는 설정값입니다. apiKey라는 이름 때문에 비밀번호처럼 보이지만, 프로젝트 주소표에 가깝습니다. 실제 방어는 6단계의 보안 규칙이 합니다. 다만 서비스 계정 키(.json 파일)는 완전히 다른 물건이니 절대 코드나 화면에 올리지 마세요.

8 수업 전날 직접 테스트

  • tool_todo.html을 열어 본인 구글 계정으로 로그인 → 할 일 추가 → 새로고침 후 남아 있는지
  • 다른 브라우저(또는 시크릿 창)에서 로그인 → 같은 내용이 보이는지
  • tool_gallery.html에서 점수가 랭킹에 올라가는지
  • 학교 네트워크에서 firebaseapp.com·googleapis.com 접속이 막히지 않는지
  • 학생 구글 계정 1개를 빌려 실제로 로그인되는지 — 교육청 계정은 외부 앱 로그인이 차단된 경우가 있습니다

마지막 항목이 이 수업 전체의 단일 최대 위험 요소입니다. 반드시 미리 확인하세요.

제미나이 캔버스 안에서는 로그인이 안 될 수 있습니다. 캔버스 미리보기는 안전을 위해 샌드박스에서 돌아가므로 구글 로그인 팝업이 막히는 경우가 있습니다. 코드가 틀린 것이 아니니, 학생에게 미리 알려 주고 배포된 자기 주소에서 확인하게 하세요. 5차시 설계가 이것 때문에 "붙이고 → 제출 → 배포 → 확인" 순서로 되어 있습니다.

부록 · 깃허브 페이지 배포 절차

킷과 학생 작품을 하나의 주소로 올리는 과정입니다. 수업 전에 킷을 먼저 올려 두고, 6차시에 학생 작품만 추가로 올리면 됩니다.

1 저장소 만들기

github.com → 로그인 → New repository. 이름은 영문으로(예: web-class).

  • 공개 범위는 Public — 무료 계정은 Public이라야 Pages가 켜집니다
  • Add a README는 체크해도 되고 안 해도 됩니다

2 킷 파일 올리기

Add file → Upload files에서 킷 폴더 안의 파일을 전부 끌어다 놓고 Commit changes.

  • index.html이 저장소 맨 위에 있어야 합니다. 폴더째 끌어다 놓으면 한 단계 안으로 들어가 주소가 달라집니다
  • shots/ 폴더는 캡처를 넣은 뒤 함께 올리세요

3 Pages 켜기

Settings → Pages → Source를 Deploy from a branch로, Branch를 main / /(root)로 두고 Save.

1~2분 뒤 같은 화면 위쪽에 주소가 나타납니다. 모양은 https://아이디.github.io/저장소이름/입니다.

4 주소를 파이어베이스에 등록

위 4단계로 돌아가 승인된 도메인에 아이디.github.io를 추가합니다. 이걸 해야 로그인 창이 열립니다.

5 학생 작품 올리기 — 세 번 있습니다

학생 파일을 받아 저장소의 works/ 폴더에 올립니다. 파일을 한꺼번에 끌어다 놓고 Commit 한 번이면 됩니다.

시점올릴 것왜
4차시 끝학습 도구 todo_*.html 5차시에 각자 주소에서 로그인을 붙이려면 먼저 올라가 있어야 합니다
5차시 중간로그인 붙인 학습 도구 학생이 같은 시간에 로그인 작동을 확인합니다
6차시 초반게임 game_*.html 전시관에 등록할 주소가 생깁니다

각 작품 주소는 https://아이디.github.io/저장소이름/works/todo_minsu.html 모양이 됩니다. 주소 목록을 미리 만들어 두고 학생에게 나눠 주면 빠릅니다.

5차시 중간 업로드가 이 수업의 유일한 시간 압박 구간입니다. 학생이 14~30분에 작업하고 제출하면, 30분쯤 한 번에 올리고 보안 규칙을 읽는 동안 반영됩니다. 38분부터 각자 주소에서 확인하면 딱 맞습니다. 미리 한 번 연습해 두시면 안심입니다.
반영이 바로 안 될 때 파일을 올린 뒤 주소에 들어가도 예전 화면이 보이면, 브라우저가 이전 내용을 기억하고 있는 것입니다. Ctrl+Shift+R로 새로고침하거나 1~2분 기다리세요. 수업 중에 조급하게 여러 번 올리면 오히려 꼬입니다.
공개 저장소라는 점 깃허브 페이지의 무료 공개 저장소는 화면뿐 아니라 코드 파일까지 누구나 볼 수 있습니다. 학생 실명·사진·연락처가 코드 안에 들어 있지 않은지 올리기 전에 한 번 훑어보세요. 파이어베이스 설정값이 코드에 들어 있는 것은 괜찮습니다 — 실제 방어는 6단계의 보안 규칙이 합니다.

요금이 나올 일이 있나

무료 Spark 요금제로 충분합니다. 20명이 6차시 동안 쓰는 읽기·쓰기는 무료 한도의 1%도 되지 않습니다.

다만 학생이 만든 코드에 저장 명령이 반복문 안으로 잘못 들어가면 짧은 시간에 수만 번이 기록될 수 있습니다. 결제 정보를 아예 등록하지 마세요. 등록하지 않으면 한도를 넘는 순간 요금이 아니라 기능이 멈춥니다. 수업에서는 그게 안전한 쪽입니다.

콘솔 사용량 및 청구에서 5차시 직후 한 번 확인해 보시길 권합니다.

수업이 끝난 뒤

  • 학생 데이터는 구글 계정 UID로만 저장됩니다. 실명은 들어가지 않습니다.
  • 학기가 끝나면 Firestore 컬렉션을 삭제하거나 프로젝트 자체를 삭제하세요.
  • 학생에게 "네 데이터를 지워 달라고 요청할 수 있다"는 점을 5차시에 알려주세요.
